# План защиты сайта

Сайт статический: на нём нет базы, входа, паролей клиентов и платежей, поэтому классический «взлом сайта» (SQL-инъекции, подбор паролей админки) ему не страшен. Реальные угрозы другие, и они ниже по списку отсортированы по тому, насколько сильно бьют.

## Что реально может пойти не так (по важности)
| # | Угроза | Чем грозит | Чем закрываем |
|---|---|---|---|
| 1 | Взлом аккаунта GitHub (украден пароль, токен, сессия) | Кто войдёт, тот перепишет сайт: подменит номер WhatsApp на свой, добавит вредоносный код | 2FA, токены с коротким сроком, защита ветки, проверка секретов перед коммитом |
| 2 | Угон номера WhatsApp и Telegram-аккаунта | Заявки клиентов уходят мошенникам | Двухэтапная проверка в WhatsApp и Telegram |
| 3 | Утечка токена бота | Кто-то управляет ботом и читает заявки | Токен только на сервере, перевыпуск через BotFather |
| 4 | Угон домена (когда он появится) | Сайт и почта клиники переходят к чужим | 2FA у регистратора, блокировка переноса, автопродление |
| 5 | Встраивание сайта в чужую страницу (clickjacking) | Клик по твоим кнопкам вслепую | `js/frame-guard.js`, либо заголовок через Cloudflare |
| 6 | Вредоносный код через сторонний ресурс | Подмена шрифтов или скриптов | Строгая CSP: сторонние скрипты запрещены, разрешены только шрифты Google |
| 7 | Копия сайта-двойник (фишинг) | Клиенты платят и пишут не тебе | Следить за выдачей, жаловаться, своя ссылка во всех соцсетях |

## Что уже сделано в репозитории
- [x] Строгая политика CSP: чужие и встроенные скрипты блокируются (проверено в браузере).
- [x] Политика реферера `strict-origin-when-cross-origin`.
- [x] `js/frame-guard.js`: сайт прячется, если его встроили на чужую страницу.
- [x] `.githooks/pre-commit`: не пускает в коммит токены GitHub и Telegram-ботов, ключи и `.env`.
- [x] Секретов в коде и в истории Git нет (сканировали).
- [x] Зависимостей нет, значит нечего взломать через устаревшие библиотеки.
- [x] Поля формы в ссылки идут через `encodeURIComponent`, в страницу их никто не вставляет (XSS закрыт).
- [x] Значения из `CONFIG` проверяются перед сборкой ссылок на WhatsApp и Telegram.

## Что нужно сделать тебе
Это то, что я не могу сделать из своей среды: настройки аккаунтов и телефона. Идём от самого важного.

### Этап 1. Сегодня, около 20 минут
- [ ] **Включи двухфакторную защиту на GitHub.** Settings → Password and authentication → Two-factor authentication. Выбирай приложение-аутентификатор или ключ доступа (passkey), а не SMS. Сохрани коды восстановления в надёжное место, а не в заметки на телефоне без пароля.
- [ ] **Защити почту, на которую зарегистрирован GitHub.** Если почту взломают, через «забыл пароль» заберут и GitHub. Включи у неё двухфакторную защиту и поставь уникальный пароль.
- [ ] **WhatsApp: двухэтапная проверка.** Настройки → Аккаунт → Двухэтапная проверка → включить, задай PIN и почту для восстановления. Никому не сообщай шестизначные коды из SMS.
- [ ] **Telegram: облачный пароль.** Настройки → Конфиденциальность → Двухэтапная аутентификация. Там же загляни в «Активные сеансы» и закрой незнакомые.
- [ ] **Удали старый токен GitHub и файл с ним.** В терминале: `rm ~/.git-credentials`. Затем GitHub → Settings → Developer settings → Personal access tokens → удали старые токены. Выпусти новый **fine-grained** токен только для нужных репозиториев, право Contents: Read and write, срок 30-90 дней.
- [ ] **Проверь, кто имеет доступ.** GitHub → Settings → Applications (разделы Authorized OAuth Apps и Installed GitHub Apps) и SSH and GPG keys. Удали всё, что не узнаёшь. В Settings → Sessions закрой незнакомые сеансы.
- [ ] **Загляни в журнал безопасности.** github.com/settings/security-log: ищи входы и действия, которых не делал.

### Этап 2. Эта неделя
- [ ] **Включи проверки репозитория.** Репозиторий → Settings → Code security (название раздела может чуть отличаться): включи **Dependency graph**, **Dependabot alerts**, **Secret scanning** и **Push protection**, а также **Private vulnerability reporting**.
- [ ] **Защити ветку main.** Settings → Rules → Rulesets → New branch ruleset: ветка `main`, включи **Restrict deletions** и **Block force pushes**. Это защитит историю от случайной или чужой перезаписи.
- [ ] **Включи HTTPS.** Settings → Pages → отметь **Enforce HTTPS**.
- [ ] **Включи проверку секретов у себя на компьютере.** В папке проекта один раз: `git config core.hooksPath .githooks`.
- [ ] **Скрой email в коммитах.** GitHub → Settings → Emails → **Keep my email addresses private** и **Block command line pushes that expose my email**. В Git: `git config --global user.email "ТВОЙ_НИК@users.noreply.github.com"`.
- [ ] **Поставь мониторинг доступности.** Бесплатный UptimeRobot на адрес сайта с уведомлением в Telegram или на почту: если сайт подменили или он упал, узнаешь сразу.
- [ ] **Включи уведомления GitHub** о безопасности (Settings → Notifications) на почту, которую читаешь.

### Этап 3. Когда появится свой домен
- [ ] Домен оформи **на клинику или клиента**, а не на себя, и включи у регистратора двухфакторную защиту, **блокировку переноса** и **автопродление**.
- [ ] Подтверди домен для GitHub Pages (Settings → Pages → Add a domain / Verified domains), чтобы никто не мог занять твой поддомен.
- [ ] Не оставляй «висячих» DNS-записей на удалённые репозитории.
- [ ] Поставь перед сайтом бесплатный **Cloudflare**: он даёт защиту от перегрузки и ботов и позволяет задать настоящие заголовки безопасности (`X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Strict-Transport-Security`, `Permissions-Policy`).

### Этап 4. Когда будет сервер или бот, принимающий заявки
Бот и сервер это уже не статика, здесь проверять нужно всё из первоначального списка (авторизация, лимиты, база, логи).
- [ ] Токен бота лежит только в `.env` на сервере (`.env` в `.gitignore`). Утёк, значит в @BotFather команда `/revoke`, новый токен.
- [ ] Команды администратора бот выполняет только для твоего `chat_id`, а не для любого, кто их написал.
- [ ] Каждое поле заявки проверяется и обрезается по длине, в базу идёт только через параметризованные запросы.
- [ ] Ограничение частоты: не больше N заявок с одного Telegram-аккаунта в минуту, иначе бота завалят спамом.
- [ ] Для вебхука задан `secret_token`, и сервер отвергает запросы без него.
- [ ] VPS: вход по SSH только по ключу, пароль выключен, включён firewall (`ufw`: открыты только 22, 80, 443), стоит `fail2ban`, система обновляется автоматически.
- [ ] Логи заявок не содержат токенов и лишних персональных данных; доступ к базе извне закрыт.

## Как проверить
| Что | Как проверить |
|---|---|
| CSP работает | Открой сайт, F12 → Console. Вставь `document.body.appendChild(Object.assign(document.createElement('script'),{textContent:'alert(1)'}))`. Окна нет, в консоли ошибка про Content Security Policy |
| Рамка блокируется | Создай локальный файл `test.html` с `<iframe src="АДРЕС_САЙТА" width="600" height="400"></iframe>` и открой его в браузере. Сайт внутри рамки должен быть пустым |
| Хук секретов | `git config core.hooksPath .githooks`, затем `echo "x=ghp_$(printf 'a%.0s' {1..36})" > test.txt && git add test.txt && git commit -m t`. Коммит должен остановиться с сообщением. Потом `git restore --staged test.txt && rm test.txt` |
| 2FA на GitHub | Выйди из GitHub и войди снова: после пароля должен потребоваться код |
| HTTPS | Открой `http://...`: должен перейти на `https://...`. В терминале: `curl -sI https://АДРЕС \| head -5` |
| Защита ветки | Попробуй `git push --force origin main`: GitHub должен отказать |
| Токен | `cat ~/.git-credentials` пишет, что файла нет |

## Если сайт взломали или подменили
1. **Не паникуй и не удаляй репозиторий.** Сначала сохрани доказательства: сделай скриншоты, скопируй `git log` и журнал безопасности.
2. Смени пароль GitHub, закрой все сеансы (Settings → Sessions), удали все токены и ключи доступа, проверь Applications и SSH keys.
3. Открой историю коммитов, найди подозрительный и откати: `git revert ХЭШ` (или верни старую версию), затем `git push`.
4. Перевыпусти всё, что могло утечь: токен бота (`/revoke` в BotFather), пароли, ключи.
5. Если подменён номер WhatsApp или Telegram на сайте, предупреди клиентов через Instagram и другие каналы и верни правильные контакты.
6. Если взломан GitHub-аккаунт, напиши в поддержку GitHub (support.github.com).
7. Когда всё исправлено, включи недостающие пункты этого плана, чтобы не повторилось.

## Принцип
Защита это не один замок, а несколько слоёв. Даже если один слой подведёт (например, ты потеряешь телефон с аутентификатором), следующий (коды восстановления, защита ветки, мониторинг) не даст беде вырасти. Чем меньше на сайте «подвижных частей», тем меньше то, что можно сломать: именно поэтому статический сайт без сервера безопаснее любой админки.
